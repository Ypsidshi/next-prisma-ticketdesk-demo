# Ticketdesk — демо кабинета заявок (Next.js + Prisma)

Коротко: небольшое веб-приложение для учёта заявок с ролями **админ / менеджер**, CRUD, фильтрами и пагинацией, экспортом в **CSV** и **журналом аудита** изменений. Стек заточен под портфолио Kwork: понятный код, Docker с PostgreSQL, миграции Prisma.

## Стек

- **Next.js 16** (App Router) + **React 19** + **TypeScript strict**
- **Prisma 6** + **PostgreSQL**
- **Zod** на границе server actions
- **jose** — подписанный **JWT в httpOnly cookie** (подход «сессия в cookie» без отдельной таблицы сессий)
- **bcryptjs** — хеш пароля
- **Docker Compose** — только сервис `db` (Postgres)

## Быстрый старт

```bash
git clone https://github.com/Ypsidshi/next-prisma-ticketdesk-demo.git
cd next-prisma-ticketdesk-demo
cp .env.example .env   # Windows: copy .env.example .env
docker compose up -d
npm install
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) — произойдёт редирект на форму входа.

Переменные окружения см. в `.env.example`. Для Docker на локальной машине `DATABASE_URL` указывает на `localhost:5432`; если поднимете приложение **внутри** той же compose-сети, замените хост на имя сервиса `db`.

## Аутентификация

Выбран **один** подход на весь репозиторий: после входа в httpOnly cookie кладётся **JWT** (HS256), в БД при каждом запросе дополнительно подгружается профиль пользователя (email, роль). Секрет — `JWT_SECRET` (в проде ≥ 32 символов).

## Демо-пользователи (после `npm run db:seed`)

| Email               | Роль    | Пароль      |
|---------------------|---------|-------------|
| `admin@demo.local`  | Админ   | `demo12345` |
| `manager@demo.local`| Менеджер| `demo12345` |

Отличие ролей: **удаление заявки** доступно только **админу**; создание/редактирование — обеим ролям.

## Сквозной сценарий (что показать заказчику)

1. Войти как **менеджер**, открыть «Новая заявка», создать заявку с заголовком и описанием, при необходимости назначить исполнителя.
2. В списке заявок применить **фильтр по статусу** и **поиск по заголовку**, пролистать **страницы** списка.
3. Открыть заявку, изменить статус (например, «В работе» → «Закрыта») и сохранить — в блоке **«Журнал изменений»** появится запись `UPDATE` с JSON снимком «до/после».
4. Нажать **«Скачать CSV»** — получить файл с текущими фильтрами (до 5000 строк в демо).
5. Выйти, войти как **админ**, удалить тестовую заявку — в журнале появится `DELETE`, строка исчезнет из списка.

## Что можно докупить (апселл)

- Полноценный **RBAC** с матрицей прав и админкой пользователей
- **Уведомления** (email/Telegram) при смене статуса или назначении
- **Вложения** к заявкам (S3-совместимое хранилище)
- **Soft-delete**, корзина, восстановление
- **Прод-деплой**: managed Postgres, секреты в vault, CI/CD, мониторинг и алёрты

## Ограничения демо

- Нет восстановления пароля, 2FA и rate limit на логин
- Экспорт CSV ограничен 5000 строками
- JWT в cookie без server-side revoke (достаточно для портфолио; в проде часто нужен refresh/revocation)
- В Next.js 16 при сборке может появиться предупреждение о переименовании `middleware` → `proxy`; на работу демо это не влияет, маршруты защищены как прежде.
